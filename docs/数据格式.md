# 行情数据格式

## 目录约定

```
data/
└── kline/
    ├── 000008.zip
    ├── 000010.zip
    └── ...
```

- 文件名 `<代码>.zip`，文件名去掉 `.zip` 即为标的代码。
- 代码只允许字母和数字（读数据时会过滤非法字符，防止路径穿越）。
- 仓库根 `data/kline/` 是**唯一数据源**：
  - PC 版：直接把这个目录作为数据源（`paths.project_data_dir()`）。
  - Android 版：`android/scripts/sync_kline_assets.ps1` 把 `*.zip` 镜像到
    `android/app/src/main/assets/kline/`，打包进 APK。

## zip 内部结构

每个 zip 里是若干 CSV，**文件名即周期**：

| 文件名 | 含义 | 前端周期键 |
|---|---|---|
| `day.csv` | 日线（必需） | `1d` |
| `week.csv` | 周线 | `week` |
| `month.csv` | 月线 | `month` |
| `60min.csv` | 60 分钟线 | `60m` |

`day.csv` 是必需的；其余周期缺失时：

- `week` / `month` 会由日线在内存里按自然周 / 自然月聚合补齐；
- `60m` 缺失则该标的无法提供分钟级视图，训练段不会被裁剪到分钟区间（见下文「多周期对齐」）。

此外，两端都会由日线**派生**这些周期，不需要在 zip 里提供：

| 派生周期 | 聚合方式 |
|---|---|
| `3d` / `5d` | 每 3 / 5 根日线合成一根 |
| `year` | 按自然年聚合 |
| `120m` | 由 `60min.csv` 每 2 根合成一根 |

## CSV 格式

标准格式带表头：

```csv
date,open,high,low,close,volume
2013-01-04,1.148,1.154,1.133,1.14,3485
2013-01-07,1.142,1.153,1.106,1.148,2368
```

### 表头

首行会被自动识别：含 `date` / `time` / `open` 任一关键字即视为表头。
表头列名**不区分大小写**，并接受这些别名：

- 日期列：`date` / `time` / `datetime`
- 其余：`open` / `high` / `low` / `close` / `volume`

### 无表头

若首行不像表头，则按位置解析，列顺序必须是：

```text
date,open,high,low,close,volume
```

volume 列可以省略（缺省按 0 处理），但不能少于 5 列。

### 编码

UTF-8，可带 BOM（`utf-8-sig`）。CRLF / LF 均可。

### 日期格式

| 周期 | 建议格式 | 说明 |
|---|---|---|
| `day` / `week` / `month` | `yyyy-MM-dd` | 取前 10 位做日期比较 |
| `60min` | `yyyy-MM-dd HH:mm` | 分钟线需要精确到分钟 |

代码里比较/分组日期时统一取字符串前 10 位，所以 `yyyy-MM-dd` 前缀必须有。

### 数值与校验

- `open/high/low/close` 必须是能转成浮点数的正数；
- `volume` 转整数，非法或缺失按 0 处理；
- 任何一行只要 OHLC 非正数、或 `high < low`、或日期为空，整行会被**丢弃**（不报错）；
- 解析后按 date 升序排序，后面的逻辑都依赖这个顺序。

> 因此：如果某只股票训练不了，先检查它的 `day.csv` 是否有大量被丢弃的行。

## 数据量要求

| 项 | 要求 |
|---|---|
| 日线根数 | 至少覆盖 `totalBars`（默认 300），否则该标的在训练时被跳过 |
| 训练段 | `displayCount + trainCount`（默认 150 + 150） |
| Android 快速起步 | 首次启动约导入 20 只即可用，其余后台继续导入 |

Android 版的相关常量（`DataInitializer.kt`）：

```kotlin
BOOTSTRAP_SYMBOLS           = 20    // 首批导入数量
BACKGROUND_BATCH_SYMBOLS    = 3     // 后台每批数量
MIN_DAY_BARS_FOR_BOOTSTRAP  = 300   // 首批要求的最少日线根数
```

## 多周期对齐（重要）

日线可能有十几年（3000+ 根），但 60 分钟线通常只覆盖最近约 243 个交易日。
如果直接在**全量日线**里随机切训练段，大部分起点会落在 60 分钟没有数据的区间，
切到分钟标签页就会看到一段和当前训练日无关的历史。

所以两端的做法一致：

1. 先把训练用的日线区间**裁剪到 60 分钟线实际覆盖的交易日范围**；
2. 周线 / 月线 / 分钟线都按同一个「切分日期」分成 `display` 与 `train` 两段。

这样任何周期标签页看到的都是**同一段时间**。对应实现：

- Android：`com.stock.trainer.domain.align.PeriodAligner`
- PC：`kline_trainer.data_source._build_periods` + `_split_by_date`

## 生成自己的数据

仓库自带 `android/scripts/export_app_kline_from_qmt.py`，用于从 QMT 导出上述格式；
`android/scripts/generate_kline_data.py` 是早期的生成脚本。两者都**不进 APK**。

替换数据的步骤：

```powershell
# 1. 把新 zip 放到仓库根 data/kline/（保持 <代码>.zip 命名）
# 2. Android 侧同步进 assets
pwsh -File android/scripts/sync_kline_assets.ps1 -Clean
```

PC 版无需额外操作，直接读 `data/kline/`。
