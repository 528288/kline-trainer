# 架构说明

两个平台共享同一套**领域概念**和同一份**行情数据**，但各自实现。本文说明两端的分层、数据流与关键设计取舍。

---

## 共同概念

| 概念 | 说明 |
|---|---|
| **Session（训练会话）** | 一次完整练习：一只股票的 `totalBars` 根日线，切成 `display`（已见历史）+ `train`（待揭示）两段 |
| **Bars** | 按周期组织的 K 线，每个周期也有 `display` / `train` 两段 |
| **AdvanceMode** | `one_step` 每次揭示一整根；`two_step` 先揭开盘、再揭收盘 |
| **TradeRecord** | 一笔成交：方向、价格、数量、盈亏 |
| **TrainingSession** | 已保存的一局记录：标的、时间、模式、统计 |
| **Vip** | 免费训练次数限制（默认 66 次）+ 支持者开关 |

数据流在两端是一致的：

```
数据源(zip/CSV)
   └─> 解析成 bars（按周期）
        └─> 裁剪到 60 分钟覆盖区间，按切分日期分成 display / train
             └─> 逐根揭示 train 段，用户下单
                  └─> 结算 → 保存记录 → 统计
```

## PC 版

### 技术栈

- 后端：**纯标准库**（`http.server` + `sqlite3` + `zipfile`），零运行时依赖
- 前端：Vue 3 + Vite + [KLineCharts](https://github.com/klinecharts/KLineCharts)，构建产物内嵌到 `src/kline_trainer/static/`
- 分发：PyInstaller `--onedir` 打包成 `KLineTrainer.exe`

选标准库而不是 FastAPI/Flask，是为了让「直接运行」只要一个干净的 Python，不用装依赖。

### 模块

```
pc/src/kline_trainer/
├── __main__.py      # python -m kline_trainer 入口
├── server.py        # HTTP 服务、路由、静态资源、参数解析
├── config.py        # 配置读写、归一化（camelCase/snake_case 双写）
├── data_source.py   # zip/CSV 解析、周期聚合、会话构建
├── storage.py       # SQLite 训练记录
├── vip.py           # 免费次数与支持者开关
└── paths.py         # 数据目录 / 用户数据目录 / 静态资源目录
```

**职责边界**：

- `server.py` 只管协议，不含业务规则；校验失败映射到 HTTP 状态码（400 / 404 / 500）。
- `data_source.py` 是纯函数式读取，除了 `day_count` 的 mtime 缓存外无状态。
- `config.py` 同时返回 camelCase 和 snake_case 两套字段名：
  前端读 camelCase，后端和旧测试读 snake_case，避免反复改名。

### HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| GET | `/api/config` | 读配置 + 数据源状态 |
| POST | `/api/config` | 存配置（白名单字段） |
| GET | `/api/symbols` | 可训练的标的列表（日线够长） |
| POST | `/api/session` | 随机开一局（消耗一次免费次数） |
| GET | `/api/vip` | 当前 VIP / 剩余次数 |
| POST | `/api/vip` | 切换支持者模式 / 重置次数 |
| GET | `/api/save-ids` | 已保存记录的「保存 ID」列表 |
| POST | `/api/runs` | 保存一次训练记录 |
| GET | `/api/runs?group_id=` | 按保存 ID 列记录 |
| GET | `/api/runs/{id}` | 取单条记录（含完整 payload） |

`/api/kline-trainer/*` 是同一批接口的别名前缀，供前端使用；两条路径行为完全一致。

### 存储

| 数据 | 位置 |
|---|---|
| 配置 | `%LOCALAPPDATA%\KLineTrainerStandalone\config.json` |
| 训练记录 | `%LOCALAPPDATA%\KLineTrainerStandalone\kline_trainer.sqlite3` |
| VIP 状态 | `%LOCALAPPDATA%\KLineTrainerStandalone\vip_prefs.json` |

命中默认数据源时**不落盘** `source_path`，这样换机器/换目录不会读到失效的绝对路径。

`kline_trainer_runs` 表把统计字段（胜率、盈亏）单独列出来方便排序，
同时用 `payload` 列保留前端原始 JSON，保证明细不丢。

### 打包

`scripts/build_exe.ps1`：构建前端 → PyInstaller → 把 `data/` 复制到 `dist/KLineTrainer/data`。
这样更新行情只要替换 exe 同级的 `data/kline`，不用重新打包。

## Android 版

### 技术栈

- Kotlin 2.1 + Jetpack Compose（Material3）
- Room（本地 K 线 / 训练记录）+ Hilt（依赖注入）
- 图表：自绘 Canvas，`ui/chart/renderer/` 下每类元素一个 Renderer
- Room schema 由 KSP 生成

### 分层

```
com.stock.trainer/
├── MainActivity.kt          # 唯一 Activity，Compose 入口 + 初始化进度页
├── StockApp.kt              # @HiltAndroidApp
├── data/
│   ├── csv/                 # CsvParser / DataInitializer：assets → Room
│   ├── local/               # Room entities、DAO、VipManager
│   └── repository/          # KLineRepository / TrainingRepository
├── domain/
│   ├── align/PeriodAligner.kt      # 多周期对齐（核心算法）
│   ├── engine/TrainingEngine.kt    # 揭示/下单/结算状态机
│   ├── engine/TrainingMode.kt      # PlayMode / AdvanceMode
│   ├── indicator/                  # MA/MACD/KDJ/RSI/BOLL 计算
│   └── model/                      # KLineData / TradeRecord / TrainingSession
├── ui/
│   ├── app/AppNavHost.kt    # 导航
│   ├── chart/               # 图表、视口、十字光标、绘制工具 + renderer/
│   ├── training/            # 训练主界面（最大的屏）
│   ├── stats/               # 统计列表与明细
│   ├── symbol/              # 标的选择
│   └── theme/               # 主题与原子组件
└── di/AppModule.kt
```

分层规则：`ui` 只依赖 `domain` 的模型和各自的 ViewModel，不直接碰 Room；
`domain` 不依赖 Android 框架（`PeriodAligner` 用了 `java.time`，靠 desugaring 支持到 minSdk 26）。

### 首次启动数据导入

APK 里带着全部行情数据（`assets/kline/*.zip`）。首次启动时 `DataInitializer` 把 zip 解压解析进 Room：

1. 先导入约 **20 只**（每只至少 300 根日线）就解锁主界面；
2. 剩余数据在**后台分批**继续导入（每批 3 只，批间有延迟，避免卡 UI）；
3. 用 `full_import_version` / `data_version` 标记数据版本，升级数据后会自动重导。

导入进度通过 `StateFlow<DataInitState>` 暴露给 `MainActivity` 的启动页。

### 存储

| 数据 | 位置 |
|---|---|
| K 线 / 训练记录 / 成交 | Room 数据库 |
| VIP 状态与训练次数 | `SharedPreferences("vip_prefs")` |

## 两端的权衡

| 决策点 | PC 版 | Android 版 | 原因 |
|---|---|---|---|
| 行情数据载体 | 磁盘上的 zip，运行时按需读 | 打包进 APK，启动时导入 DB | 手机没有「数据目录」概念，且需要离线可用 |
| 数据读取时机 | 每次开一局现读 zip | 一次性导入 → Room 查询 | 手机端解析 zip 比查 SQLite 慢，且要避免重复解析 |
| 图表实现 | KLineCharts（成熟 Web 图表库） | 自绘 Canvas | Web 有现成的高性能 K 线库；Compose 上没有同等成熟度且可控的方案 |
| 依赖重量 | 零运行时依赖 | Compose + Room + Hilt | PC 要「下载就能跑」；Android 本来就是重量级 |
| 免费次数 | `vip_prefs.json` | `SharedPreferences` | 各平台最自然的本地持久化 |

## 多周期对齐

两端都实现了同一件事：把训练段的日线裁剪到 60 分钟线覆盖的区间，再按同一个切分日期
拆 `display` / `train`。细节见 [数据格式.md](数据格式.md#多周期对齐重要)。

## 已知限制

- **数据不自动更新**：行情数据是静态快照，需要自己替换 `data/kline/`。
- **免费次数是本地计数**：清理数据/重装会重置，只做轻量引导，不是真正的授权系统。
- **PC 版监听 127.0.0.1**：默认只对本机开放；`--host 0.0.0.0` 可对外，但没有鉴权。
- **多周期对齐依赖 60 分钟数据**：完全没有 `60min.csv` 的标的只能做日线训练。
